# 0002 审批服务不产生业务单据，对业务系统只提供数据接口

状态：已采纳（2026-10-13 用户确认）
日期：2026-10-13
关联：T-000

## 背景

设计初稿里，审批中心可以直接填表发起审批（请假、报销），还打算给业务系统提供 Vue 组件、WinForms 控件、ASP.NET Core 扩展。用户明确：审批服务只做中间处理（流程绘制、审批流转、节点和审批记录），对外提供服务，自己不产生业务单据；界面组件不提供，只提供数据接口。

## 决定

- 所有审批都由业务系统通过接口发起；撤回、重新提交、作废后终止也由业务系统调接口。审批中心不提供发起，也不能改业务数据。
- 业务单据的创建、修改、保存、作废和单据状态都在业务系统里。审批服务只保存审批要用的数据快照，审批人填写的字段（如核定金额）随回调带回，由业务系统决定怎么更新单据。
- 原来的“表单设计器”改成“审批数据与详情展示”：定义业务系统要传的字段、发起时校验、审批人看到的排版。
- 对业务系统只提供数据接口：开放接口（OpenAPI 文档）和 .NET SDK。不提供 Vue 组件、WinForms 控件、ASP.NET Core 扩展；业务系统的待办和审批界面三选一：带免登录链接跳到审批中心、内嵌审批中心页面、用接口自己画。
- 示例业务系统把这些界面做一遍，给业务系统照着改（ADR 0005）。

## 备选方案

- 审批中心也能发起纯 OA 单据：会让审批服务开始管业务数据，和“中间服务”的定位冲突，用户否决。
- 提供界面组件：要跟着各业务系统的界面风格和框架版本走，维护成本高；以后需要再讨论。

## 影响

- AGENTS.md 加了硬性规则 R14，任务里出现越界需求时停下来问。
- 设计书 V0.5 起按这个边界写；试点的费用报销、采购申请都从示例业务系统提交。
