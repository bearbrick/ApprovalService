# 0003 审批库和业务库分开，不做直连业务库的数据库连接器

状态：已采纳（2026-10-13 用户确认）
日期：2026-10-13
关联：T-000

## 背景

设计稿里有一种接入方式是“数据库连接器”：审批服务直连业务库，按扫描 SQL 自动发起、按回写 SQL 改状态，给改不动代码的老系统用。用户的答复是审批库最好和业务库分离，做独立服务。

## 决定

- 审批服务用自己独立的数据库，不和任何业务系统共用库，也不连业务系统的库。
- 业务数据只通过接口进出：取数接口、钩子、回调。审批库里只存审批要用的快照。
- 去掉数据库连接器；接入方式剩三种：接口加回调、待办和审批界面（跳转、内嵌或自己画）、流程里调业务。

## 备选方案

- 保留数据库连接器：对老系统改造最少，但审批服务要拿业务库的账号、依赖业务库的表结构，边界不清、安全风险大。公司的业务系统都是自己的 .NET 系统，能改代码，用不上。

## 影响

- 接入应用不再保存数据库连接串。
- 以后真遇到改不动代码的外购系统，再单独写 ADR 讨论（比如由一个小的适配服务代为对接）。
