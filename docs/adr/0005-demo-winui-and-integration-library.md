# 0005 示例业务系统用 WinUI 3 做界面，对接代码放在不依赖界面的类库里

状态：已采纳（2026-10-13 用户确认）
日期：2026-10-13
关联：T-017、T-018

## 背景

需要一个示例业务系统，演示对接全流程和业务系统要改多少，两个试点（费用报销、采购申请）都从它提交。公司的 C/S 系统都是 WinForms，Web 系统是 Vue + .NET 10。用户想用 WinUI 3 展示精致的界面，同时不妨碍业务系统抄对接代码。

## 决定

- 示例业务系统分两个项目：
  - `ApprovalService.Demo.Integration`：对接类库，编译到 net48 和 net10.0，只引用 SDK，不依赖任何界面框架。提交审批、撤回、待办、回调处理、取数接口、钩子都在这里。业务系统照抄它，界面换成自己的。
  - `ApprovalService.Demo.WinUI`：WinUI 3 界面（.NET 10、Windows 10 以上），只引用对接类库；打包成免安装的，自带 Windows App SDK 运行时。
- 示例系统自己画待办角标、待办列表、审批窗口（调数据接口），另外演示内嵌审批中心页面（WebView2）。
- 自检（`--smoke`）直接调对接类库跑演示场景，不经过界面。

## 备选方案

- 用 WinForms 做界面（和标签服务的演示程序一样）：和公司的 C/S 系统一致，能演示 .NET Framework；但用户想展示更好看的界面。把对接代码拆到类库里以后，用 WinUI 3 不影响照抄。

## 影响

- 要从 nuget.org 下载 Windows App SDK（本机缓存里没有，几百 MB），按 AGENTS.md R8 先征得用户同意。
- .NET Framework 的兼容由对接类库在 net48 下编译、调用端检查程序覆盖，不靠界面。
