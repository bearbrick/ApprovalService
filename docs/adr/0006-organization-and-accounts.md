# 0006 组织架构自己维护、业务系统绑定；账号先独立，登录按统一登录预留

状态：已采纳（2026-10-13 用户确认）
日期：2026-10-13
关联：T-007

## 背景

找审批人（直属上级、部门负责人、分管领导、角色……）全靠组织架构。长远看公司要有主数据系统统一管理组织、有统一登录把各产品整合成平台；现在都没有，业务系统里的组织数据也不全。

## 决定

- 审批服务自己维护一套组织架构：部门树（负责人、分管领导）、人员（工号、手机、邮箱、岗位、职级、直属上级、在职状态，可以在多个部门）、角色。初始化用 Excel 导入，导入前检查工号重复、上级不存在、上下级绕圈。
- 业务系统通过“绑定”关联：每个接入应用一张对应表，业务系统的用户 ID、部门 ID 对应审批服务的人员、部门；绑定后接口里可以直接用业务系统自己的 ID。
- 业务系统（以后是主数据系统）调接口推送人员、部门变更；每类数据指定一个可信来源（现在是审批服务自己），其他来源只更新绑定和补充字段，不覆盖。组织的每次改动留记录。
- 账号先独立：人员开通账号后用工号和密码登录；从业务系统进来用嵌入令牌免登录。登录这一层按 OIDC 设计，以后公司统一登录上线时，审批服务和标签服务一起接进去，账号按工号对上。
- 登录令牌按 App 也能用的方式发（短期访问令牌 + 刷新令牌），不只靠浏览器 Cookie。

## 备选方案

- 直接用某个业务系统的组织架构：数据不全，而且会让审批服务依赖那个系统。
- 现在就接企业微信或钉钉的通讯录：只预留，先不做（设计书第 6 节）。

## 影响

- 组织架构来源做成扩展点（`IOrganizationSource`），以后换成主数据系统时审批核心不动。
