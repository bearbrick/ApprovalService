# 0007 流程设计统一使用自由画布

状态：已采纳（2026-10-13 用户明确要求取消钉钉式设计，直接使用自由画布）
日期：2026-10-13
关联：T-024、T-001、T-008、T-009

## 背景

最初方案保留树形与自由画布两种设计器。原型评审时，用户明确要求一步到位采用自由画布，并把常用审核需求考虑完整。当前只有演示原型，正式流程定义契约和引擎尚未实现，不存在已发布生产流程的迁移负担。

## 决定

- 全部流程使用同一个自由画布，支持开始、结束、审批、办理、抄送、排他 / 包容 / 并行网关、子流程和自动节点；不再提供树形入口或画法转换。
- 简单流程通过模板、节点属性面板和校验提示降低配置难度；复杂流程在同一画布表达回路、条件与并行汇合。视觉继续沿用标签服务。
- 画布设计 JSON 编译成执行图；执行图、令牌、统一命令和纯引擎的既有决定不变。正式文件仍计划使用带本系统扩展的 BPMN 常用子集。
- 审批规则和节点属性独立于布局：14 种审批人来源、4 种多人方式、操作权限、字段权限、退回重提、委托、异常人员、时限提醒、子流程和出站失败均需有明确配置与验收场景。
- 初版仍不做定时 / 消息事件、补偿事务、超时自动同意或拒绝；通用画布不等于支持全部 BPMN 语义。业务单据由业务系统产生，审批中心不修改业务字段。

## 备选方案

继续维护两种设计器：可分别优化简单与复杂流程，但产生双模型、双校验反馈及转换成本，与本次用户决定不符。

## 影响

- ADR 0004 仅“双画法及转换”部分被本决定取代，其余引擎决定继续有效。
- 同步设计书第 1、2、3、9、15 节、架构、规划契约、仓库说明和未认领任务。T-008 负责工作台与审批属性；T-009 负责画布图形交互，两者组成同一产品入口。
- 不修改已实现的开放接口、SDK 或生产功能；原前端骨架仅同步占位说明。T-025 独立工作树的通用框架不受影响，后续集成时以本决策为准。
- 原型旧草稿需保留可恢复数据并升级为画布；原型 JSON 不作为正式 BPMN 或生产契约。
