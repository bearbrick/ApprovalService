# 0011 本地账号使用短期 JWT 与可轮换刷新令牌

状态：已采纳
日期：2026-10-20
关联：T-007

## 背景

审批中心需要浏览器和手机网页共用的登录令牌，当前没有公司统一登录。首次登录改密码、密码变更和管理员令牌作废都必须在后续请求中生效。设计书与 ADR 0006 要求将本地登录封装成可替换的身份层。

## 决定

访问令牌使用 15 分钟有效的 HS256 JWT，刷新令牌使用数据库保存 SHA-256 摘要的随机令牌，消费后立即轮换。账号的令牌版本随改密码和管理员作废递增，JWT 验签后回库核对版本、在职与启用状态。一次性嵌入令牌也只保存摘要，5 分钟有效，原子消费；签发时必须先鉴权接入应用并将外部用户 ID 解析成内部人员 ID。首次登录令牌带改密码标记，受保护业务接口拒绝它。签名密钥可从部署配置读取；未配置时在数据目录创建随机密钥文件，不提交仓库。

使用与标签服务一致且本机已缓存的 `Microsoft.AspNetCore.Authentication.JwtBearer` 10.0.12、`Microsoft.IdentityModel.JsonWebTokens` 8.19.2。接口层负责 JWT 验证和路由授权；密码摘要、令牌签发与持久化只在基础设施层，应用层只依赖抽象。未来切换 OIDC 时保留应用层身份边界。

## 备选方案

只靠浏览器 Cookie 无法直接覆盖手机 App，也不方便业务系统嵌入。自写 JWT 编码和验签容易遗漏算法限制与过期校验，因此沿用标签服务的成熟包。

## 影响

基础设施和接口层新增上述两个已缓存依赖，数据库增加账号、刷新令牌、嵌入令牌表。部署时必须保护数据目录中的签名密钥与数据库；多实例部署应显式配置同一签名密钥。统一登录上线时需提供新的身份适配实现，不能直接信任业务系统提交的用户 ID。
