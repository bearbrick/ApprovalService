# 0013 开放接口只接受接入应用已绑定的人员 ID

状态：已采纳
日期：2026-10-20
关联：T-006、T-007

## 背景

设计书和现有契约允许业务系统以工号或已绑定的业务用户 ID 调用开放接口。当前 `ResolvePersonAsync` 在找不到绑定时按全局工号回退。任一接入应用只要知道另一名在职人员的工号，就可能以该人员身份查询或操作其待办；API Key 只证明应用身份，不能证明它有权代表该工号。嵌入令牌签发已单独改为必须存在本应用绑定，但 T-006 开放查询和任务接口仍需统一确定这项语义。

## 决定

开放接口中的 `userId` 仅接受 `(clientAppCode, externalUserId)` 已建立的绑定，不做全局工号回退。工号或手机号只用于本应用来源人员的自动绑定；跨来源人员由本地组织管理员确认绑定。业务系统先完成绑定，再以自己的外部用户 ID 调用待办、任务和嵌入签发接口。

## 备选方案

继续允许工号直传最省接入步骤，但 API Key 无法证明应用有权代表这个人。只禁止嵌入签发而保留任务接口的工号回退，仍会暴露跨应用待办和审批操作，不足以关闭身份边界。

## 影响

用户已确认收紧身份边界。T-007 的通用人员查询不再回退全局工号；T-006 的开放发起、任务操作及其他代表人员的路由统一调用严格绑定解析。完整开放接口语义与 SDK、`docs/contracts.md`、设计书的同步由 T-006 集成时完成；已有调用方须先为应用建立人员绑定。
