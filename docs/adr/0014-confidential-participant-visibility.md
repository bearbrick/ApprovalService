# 0014 保密流程按发布版本和实际参与记录控制附件可见性

状态：已采纳
日期：2026-10-23
关联：T-043

## 背景

普通抄送节点不要求已阅时不会生成任务，单靠任务表无法确认谁收到抄送；任务改派后也不能仅凭当前指派人还原实际处理人。附件下载若只核对发起人和任务表，会误拒抄送收件人，并可能让已取消任务的旧指派人在保密流程中继续查看。

## 决定

流程定义可选 `isConfidential`，发布时固定到执行图；旧定义及旧执行图缺省为 `false`。用户确认保密流程的参与人为发起人、实际代发人、当前及实际处理过人工任务的人员、已送达的普通或人工抄送收件人，历史参与人保留可见性。管理员与额外查看人不会因身份自动获得保密附件权限。嵌入会话还须属于审批单来源应用。

普通抄送到达时在纯引擎事件中固定实际解析的收件人；人工抄送使用已审计的目标人，任务完成、转交、退回与要求补充使用已审计的实际操作人。运行提交在同一数据库事务写入按审批单、人员和来源去重的历史参与人投影，供权限查询；收件通知是否异步送达不改变审批单内已经记录的抄送授权。

## 备选方案

只扫描操作事件或当前运行状态：无法高效查询四列表，普通抄送事件原本没有收件人，且易受后续组织变动影响。给所有管理员或曾被指派的人默认访问：与保密范围不符。

## 影响

三种数据库均新增历史参与人表；现有流程 JSON 不升级格式版本。旧审批单没有可凭空推断的普通抄送收件人，不能从当前组织关系回填其权限；历史上有已阅任务的人仍按任务事实可见。审批中心查询也应使用同一投影和保密边界。
