# 0015 标准 BPMN 建模器负责流程图编辑

状态：已采纳（2026-10-23 用户要求直接使用 BPMN 建模器，并同意下载依赖）
日期：2026-10-23
关联：T-046

## 背景

现有正式设计器用自绘 SVG 表达 BPMN 常用子集，虽然支持流程文件互导，但图形端口、连线路由和拖拽编辑质量未达到评审要求。用户要求使用成熟 BPMN 建模器，不再维护自绘图形交互。审批服务已有完整的流程 JSON 契约和纯执行引擎，不能把图形库当作审批规则或运行时引擎。

## 决定

- 前端引入 npm 官方仓库的 `bpmn-js` 18.16.0（2026-05-04 发布），固定版本并提交锁文件。用户已批准下载。选择 Modeler 提供 BPMN 2.0 元素、连线、编辑、缩放与选择；工具箱和建模规则仅开放审批服务支持的子集。
- 审批服务的 `FlowDefinition` 仍是流程配置与发布的权威数据；标准 BPMN 模型负责画布展示与交互，适配层转换节点、连线、坐标和名称。审批人来源、会签、字段权限、退回等继续留在现有工作台属性面板与执行引擎，不交给图形库解释。
- 现有带审批扩展的 BPMN 导入导出协议保持不变；通用外部 BPMN 文件不自动成为可发布的审批流程。后续如需保存自由折线坐标，再以向后兼容的可选布局字段修改权威契约。
- 保留并确保 bpmn.io 标识可见，满足该库许可证要求。产品仍保持标签服务的颜色、布局与操作风格。

## 备选方案

- 继续改进自绘 SVG：需要自行维护 BPMN 形状、端口、连线和编辑行为，已出现路由缺陷，后续维护成本高。
- LogicFlow：可绘制流程图，但仍需更多自定义才能达到标准 BPMN 建模和互操作的目标。

## 影响

- 新增前端第三方依赖并增加前端包体；后端执行图、数据库和开放接口本次不变。
- 画布组件与测试需重写图形适配部分，工作台 `FlowDefinition` 接口保持兼容。
- 同步 `frontend/README.md`、`docs/architecture.md` 和设计书相关实现描述；原 ADR 0007 的统一自由画布决定继续有效。
