# 0015 按接入应用限制审批中心内嵌来源与一次性令牌交换

状态：已采纳
日期：2026-10-23
关联：T-011、T-020

## 背景

业务系统需要在 iframe 或 WebView2 中免登录打开审批中心。仅签发一次性嵌入令牌不能限制哪些网页可装载页面；不限定 `postMessage` 目标又会把审批结果发给不可信窗口。接入应用尚无允许嵌入来源配置。

## 决定

每个接入应用保存 `AllowedEmbedOriginsJson`，默认空数组。管理接口只接受完整 HTTPS origin（协议、主机、可选端口），开发环境的 `http://localhost` 与 `http://127.0.0.1` 可用；拒绝路径、查询、片段、通配符和用户信息，去重后最多 20 项，每项最长 256 字符。提供内嵌文档的服务端按所属应用设置 CSP `frame-ancestors 'self'` 加登记来源；未登记来源不可内嵌。部署时同源前端入口须经过此安全响应，不能让静态文件服务器绕过该头。

业务系统后端取得五分钟、一次性嵌入令牌后，将令牌放在审批中心地址的 URL `#` 片段中。页面读取后立即从地址栏和历史条目清除令牌，再向交换接口提交；服务端令牌仍按原协议原子消费，并在每次中心查询和操作中校验人员、接入应用及身份代际。页面完成审批后只向已登记的来源使用明确的 `targetOrigin` 发送不含令牌及业务数据的 `postMessage`，消息只含审批单 ID、任务 ID 与状态变化提示。

## 备选方案

将令牌放查询参数会进入请求日志和来源引用；`postMessage('*')` 或仅靠前端检查父窗口来源不足以约束页面装载；全站开放 iframe 会允许未登记网站嵌入已登录页面。

## 影响

三种数据库增加允许来源列并生成迁移；T-020 提供管理配置，T-011 提供受限内嵌入口、兑换和完成通知。旧应用默认无可用外部内嵌来源；普通新窗口登录不受影响。开发服务与生产静态托管都须保持 CSP 头的等效安全边界。
