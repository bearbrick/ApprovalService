# 0017 审批中心使用人员 JWT 执行任务命令并返回逐项许可

状态：已采纳
日期：2026-10-23
关联：T-011

## 背景

已有开放任务接口使用接入应用 API Key 和本应用人员绑定。审批中心的操作者是登录人员；让浏览器持有 API Key、填写外部用户 ID 或自行推断节点许可，均会越过真实身份与流程规则。

## 决定

中心详情对每项任务返回服务端按当前已验证 JWT 人员、嵌入应用范围、任务状态及发布节点规则计算的可尝试操作编码；最终执行仍由统一引擎在提交时再次验证权限、状态和必填参数。写接口只接受 JWT，从会话取得实际操作人，按审批单归属限制嵌入会话；目标人员使用可信内部人员 ID 并验证在职与可用范围，服务端自行构造组织快照、业务钩子输入与运行命令。浏览器只显示详情明确返回的操作，不用本地规则扩大权限。

批量同意按逐任务独立处理，返回每项成功或结构化错误；某项失败不回滚此前成功项。操作完成后重新读取列表、详情和角标；嵌入模式按 ADR 0016 通知登记来源。审批数据快照仍只能由业务系统维护，审批人字段沿用节点权限和既有校验规则。

## 备选方案

直接复用 API Key 开放接口会把长期密钥交给浏览器；只在前端根据任务状态显示操作会遗漏代理、节点配置和并发状态；批量全部回滚会让单张过期任务阻断其余审批。

## 影响

中心契约新增详情任务许可、JWT 写入及逐项批量响应；后端仍只通过应用层调用引擎统一入口。前端不存 API Key，不提供发起审批或修改业务单据的表单。
