# 0018 流程管理按直属部门授权，草稿和发布版本分离

状态：已采纳
日期：2026-10-24
关联：T-020

## 背景

运行库目前只有流程元数据和不可变的发布版本，没有草稿、修订号、停用状态或明确的部门归属。`AdministratorId` 的旧注释写成工号，离职交接却把它作为内部人员 ID 使用。设计书要求部门流程管理员只管理自己的流程，并允许本服务兼容的 BPMN 文件在环境间迁移。用户已确认授权、发布和导入导出的具体边界。

## 决定

- `Flow.AdministratorId` 统一保存内部人员 ID，继续供现有运行期离职交接等找人规则使用；此字段自身不授予流程管理权限。存量值同时按人员 ID 和工号查找，只在去重后唯一匹配时自动改写；零匹配或多匹配保存待人工处理事项，不能按任一候选人猜测。
- `Flow.OwnerDepartmentId` 为可空的直接所属部门。当前在职且持本地会话的组织管理员可管理全部流程；持 `flow-admin` 角色的在职本地人员仅可管理自己直接加入的 `OwnerDepartmentId` 对应流程。上级部门关系不继承权限，无所属部门的流程仅组织管理员可管理。
- 每个流程只有一份带递增修订号的可编辑草稿。发布前编译并校验完整执行图，并同时核对预期草稿修订及预期当前发布版本；在一个事务内追加不可变 `FlowVersion`、切换当前版本并记录操作者、原因、版本号和内容 SHA-256。发布版本不得编辑或删除。恢复旧版内容须复制到草稿后重新发布为新版本。
- 停用只阻止新的审批单发起；已在途审批单继续按照发起时锁定的发布版执行。本服务兼容的 BPMN 导入先预检，仅写入草稿。同编码默认冲突；显式指定目标流程和预期草稿修订才可覆盖。导出明确选择草稿或不可变发布版。审计记录只留操作者、原因、版本与内容 SHA-256，不保存完整流程 JSON。

## 备选方案

按流程管理员工号授权会混淆外部标识与内部身份，也无法表达部门直接归属；按部门树继承会扩大管理范围。直接修改发布版或用导入内容覆盖已发布流程会破坏在途审批的版本可追溯性。自动挑选歧义标识的第一个人员会把原权限和运行期找人行为交给错误人员。

## 影响

流程管理仓储和受保护 HTTP 用例需实现授权、乐观并发、原子发布及安全审计。数据库三种提供程序需新增所属部门、草稿及待人工处理事项模型。已有开放发起和离职交接仍使用发布版及 `AdministratorId`，不得把管理角色直接替代运行期指定管理员。管理后台须明确展示未完成的存量身份处理事项；管理 API 契约和设计书实现同步由对应切片完成。
