# 0019 报表查询范围与保密统计

状态：已采纳
日期：2026-10-24
关联：T-058

## 背景

报表汇总可能跨流程、部门与人员；仅靠浏览器筛选或管理员菜单控制不足以保护保密流程。部门负责人的下级部门范围和服务接口此前没有明确约定。

## 决定

新增四条本地 JWT 保护的 GET JSON 报表接口：`/api/v1/admin/reports/overview`、`/flows`、`/nodes`、`/people`。请求必须给出 UTC 半开时间区间，可筛选流程、来源应用和发起时部门快照。组织管理员可查询全部或指定部门；当前在职部门负责人只可查询其**直接负责**的一个或多个部门，不自动包含下级部门。服务端从已验证令牌取人，每次查当前组织角色和负责人关系；嵌入会话不可调用。

保密性以审批单锁定的发布版本为准。保密流程只进入匿名发起量、结束量，不输出流程编码、节点、人员或审批单明细。公开流程的指标在查询时跨期读取必要事实并计算；当前待办以服务端观察时刻为准。

## 备选方案

前端自行限制筛选无法保护 HTTP 接口；按组织树自动扩展下级部门会扩大用户确认的负责人范围；对保密流程输出节点和人员指标可能间接暴露参与者。

## 影响

Contracts 定义路由、参数和响应模型，接口层只转交认证身份与查询条件；应用层核对管理范围，事实层按部门集合过滤。小时汇总、导出和报表页面仍由后续任务实现。
