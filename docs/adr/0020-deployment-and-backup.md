# 0020 单实例部署、受限指标与 SQLite 在线备份

状态：已采纳（2026-10-24，按 T-021 已评审的部署目标和标签服务同类实现）
日期：2026-10-24
关联：T-021

## 背景

审批服务初版用 SQLite 和本地附件，也要能在 Linux 容器或 Windows 服务中运行。活动 SQLite 数据库有 WAL，直接复制数据库文件不能当成一致备份。指标不能把审批单号、人员或 URL 查询参数暴露给监控系统。

## 决定

- 一个数据目录只运行一个服务进程。Docker 用官方 .NET 10 运行时、多阶段构建已锁定的前端和后端，非 root 运行，数据目录挂持久卷。Windows 用 .NET 官方 Windows 服务宿主，包 `Microsoft.Extensions.Hosting.WindowsServices` 10.0.12 已在本机缓存，版本与标签服务一致。
- `/metrics` 输出 Prometheus 0.0.4 文本，只用服务端路由模板、HTTP 方法和状态码作标签，不保留真实 URL、人员、业务单号或正文；默认只接受本机来源。部署方可配置至少 32 字符的 `ApprovalService:Metrics:BearerToken` 开放带 Bearer 密钥的远程采集，必须放在受控内网或 TLS 代理后，不把路径直接暴露到公网。
- SQLite 每日按服务器本地时间 02:30 在线执行 `VACUUM INTO`，随后复制数据目录内本地附件和登录签名密钥；保留最近 7 份完成的每日快照。服务重启后同一天不重复备份，过了计划时刻才启动时补做当天快照。
- 发现数据库存在待执行迁移时，先做 `preupgrade` 快照；快照失败即拒绝迁移。升级前快照不自动删除，由部署人员确认升级成功后清理。恢复必须停服务，移走旧数据库及 WAL/SHM，恢复主库、附件和签名密钥；接入应用加密主密钥由部署环境另行备份。
- SQL Server、PostgreSQL 使用各自数据库工具做备份，内置每日任务仅在 SQLite 运行。

## 备选方案

- 直接复制活动 `.db`：WAL 中的已提交事务可能没有进入主文件，恢复会丢数据。
- 新增 OpenTelemetry Prometheus 导出包：当前有限的 HTTP 指标可用 .NET 内置设施和少量代码实现，避免引入额外依赖；以后平台统一监控时再替换。
- 用计划任务代替进程内每日备份：每套部署都要额外配置且容易漏设；保留 `backup-now` 命令供管理员手工补做。

## 影响

- 新增一个已缓存、与标签服务同版的微软 NuGet 包，集中写在 `backend/Directory.Packages.props`。无新的 npm 包。
- Docker 镜像未能在本机实际构建，因为开发机没有 Docker；Windows 服务安装需要目标机管理员权限。运行与恢复步骤见 `backend/deploy/README.md`，后端检查程序演练快照与恢复。
