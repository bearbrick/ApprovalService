# 0021 流程模拟与接入测试使用互相隔离的协议

状态：已采纳
日期：2026-10-24
关联：T-022

## 背景

流程管理员要在发布前验证草稿，又不能因为测试模式创建真实审批单或触发业务系统。接入管理员还需要验证回调地址和验签配置。两种测试的外部副作用要求不同，用户已分别确认。

## 决定

流程模拟仅允许本地组织管理员或该流程管理员使用。创建时提交完整草稿、假审批数据、假发起人和各人工节点假处理人；会话保存在进程内存，闲置三十分钟过期，只有创建人能逐步操作、读取和删除。人工任务、网关和流程完成仍由同一个纯引擎计算；自动动作和子流程必须显式提交假结果。此模式不创建审批单或待发项，也不发送真实提醒、钩子和回调。

测试回调另由本地组织管理员或已登记的该应用管理员填写原因后触发，使用新增 `integration.test` 合成事件，经既有 HMAC 签名、持久待发队列和发送日志投递。事件与审批单和业务动作无关，接收方只验签确认。组织管理员维护每个接入应用的管理员内部人员 ID 名单，旧应用默认空名单。

## 备选方案

复用真实审批单发起接口会占用业务单号并可能触发通知和钩子。测试回调直接同步发送则无法复用已有的重试与投递留痕。两者均不采用。

## 影响

模拟接口需新增管理契约、进程内存容器和权限场景检查。测试回调及应用管理员名单需要独立实现增量迁移和管理 API；完成之前接入向导的“一键测试回调”仍不可用。设计书第 11 节及契约文档同步已实现的模拟语义。
