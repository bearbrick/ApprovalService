# 架构决策记录（ADR）

跨部分或跨模块、难以回退、或者以后有人会问“为什么这样做”的决定，写一篇 ADR。一篇只记一个决定，写完不改内容；决定被推翻时新写一篇，把旧的状态改成“已被 00xx 取代”。

什么时候必须写：

- 改契约（开放接口、错误码、HTTP 头、回调、流程定义 JSON）中不向后兼容的部分
- 新增或替换第三方依赖（包括升级主版本）
- 改变依赖方向、项目划分、部署方式
- 放宽 AGENTS.md 里的任何硬性规则

文件名：`四位编号-英文短名.md`，编号取当前最大值加 1。多个 AI 同时写 ADR 时编号可能撞车，合并时后合并的一方改号。

## 模板

```markdown
# 00xx 标题（一句话说清决定）

状态：提议 / 已采纳 / 已被 00yy 取代
日期：yyyy-MM-dd
关联：T-xxx

## 背景
为什么要做这个决定，有哪些约束。

## 决定
具体做什么。

## 备选方案
考虑过但没选的方案，以及没选的原因。

## 影响
对代码、兼容性、其他任务的影响；需要同步修改的文档。
```
