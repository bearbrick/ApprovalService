# 审批服务高保真交互原型

本原型用于评审页面、配置和操作路径，视觉对齐标签服务最终页面。使用虚构数据和浏览器本地状态，不连接生产接口。生产前端仍在 `frontend/`，这里不替代正式开发任务。

## 打开原型

在仓库根目录运行（仅使用 Node 内置模块，无需安装依赖）：

```powershell
node docs/prototypes/serve.cjs
```

打开 [流程设计器](http://127.0.0.1:4174/designer.html) 或 [原型评审导航](http://127.0.0.1:4174/index.html)。端口可用环境变量 `APPROVAL_PROTOTYPE_PORT` 调整。服务只监听本机，只提供原型目录中的文件。

## 设计覆盖与边界

统一自由画布决定见 [ADR 0007](../adr/0007-single-canvas-designer.md)。[常用审核场景清单](approval-scenarios.md) 按正常路径、人员异常、退回协作、时限权限和外部失败列出 16 类评审场景及正式实现的边界。

| 设计书章节 | 原型对应 |
| --- | --- |
| §1 初版范围、§3 设计器、§4 审批规则 | [设计器覆盖清单](designer-coverage.md)，审批中心和管理后台补充操作侧入口 |
| §5 数据与详情、§7 打印 | 设计器数据、排版和打印页签；审批中心只读详情与打印预览 |
| §6 审批中心与手机端 | [审批中心覆盖清单](center-coverage.md) |
| §8 报表、§9 文件、§10 平台预留、§11 组织账号 | [管理后台覆盖清单](admin-coverage.md)，登录页补充账号体验 |
| §12–13 接入与接口 | 管理后台接入向导、接口调试、钩子及回调队列；业务示例的对接说明 |
| §14 示例与试点 | 费用和采购业务样例、17 个场景卡片；设计器另有合同并行和质量返工样例 |
| §2 架构、§9 引擎、§15 计划 | 属于生产实现与任务管理，不用原型页面冒充后端能力 |

- 设计器四套流程分别保存草稿和发布摘要；原型已有图结构检查和有限连线路径推演。正式 BPMN、复杂表达式、并发令牌、计票及生产执行图编译仍未实现。
- 设计器的 26 个场景含预置条件结果；手动改金额不会自动重算 needsGeneralManager / needsFinanceReview 等辅助值。正式版由引擎计算审批规则，原型辅助字段不是新增接入要求。
- 桌面与手机审批共享本地审批记录和草稿。管理后台、设计器、业务示例各有独立演示数据，跨模块跳转不等于生产链路联调。
- 示例业务场景按预置路线推进：提交、撤回、同意、拒绝、退回、补充、重提会改变本地状态；17 个入口不代表已实现 17 套引擎规则。相邻去重、权重票签、并行会审等只展示配置与路径意图。
- 示例中的回调记录、接口测试、邮件、权限、组织同步、附件访问、存储迁移均为本地模拟；不发送请求。报表使用固定演示统计，导出为 CSV。
- 打印使用 HTML 预览和浏览器打印；无服务端 PDF、真实二维码、正式电子签章或附件合并能力。
- 登录页只判断演示输入，密码不保存；不要输入真实生产凭据。统一登录、ESB 等只展示预留位置。
- 业务单据仅在示例业务系统创建和修改，审批中心只读；撤回、重提均位于业务系统。

演示数据保存在当前来源的 `localStorage`。业务示例提供“重置样例”；其他模块需要恢复初始状态时，可在浏览器开发工具中删除名称以 `approval-prototype-` 开头的原型数据。不会操作标签服务的数据。

## 视觉与验证

基准：`http://localhost:5173/#/t/A4_SHIPPING_MARK/fields`。沿用 56px 深蓝顶栏、280px 浅色侧栏、蓝色主操作、下划线页签、紧凑表格、品牌图片和现有图标。桌面以 1280×720 核对，手机以 390×844 核对。

[视觉与交互验收记录](design-qa.md) 保存检查结果，`evidence/` 保存页面证据。全量仓库验证通过：后端 55 项、调用端 26 项（含真实服务端到端）、前端 5 项以及构建和格式检查；原型另做脚本语法、65 项图检查和浏览器交互检查。可运行 `node docs/prototypes/checks.cjs` 重复核对。
