# WinUI 3 客户端与对接设计

这是设计书第 12、14 节及 ADR 0005 的界面展开，不是新增客户端产品。打开 [桌面客户端原型](winui.html)；原有 [网页业务示例](demo.html) 保留 17 个场景的快速演示。

## 项目与职责

| 层 | 职责 | 当前实现状态 |
| --- | --- | --- |
| WinUI 3 示例界面 | 单据列表与编辑、预览提交、进度、待办角标、原生审批窗口、WebView2、身份与连接状态 | 本次用 HTML 模拟桌面交互；正式 WinUI 项目待建 |
| Demo.Integration（net48 / net10.0） | 将业务单据转换为审批输入；提交、撤回、重提、查询；回调验签去重、业务状态回写；本机业务后端的取数、取人、预算钩子和生成订单 | 当前只有服务信息最小链路；其余由 T-017 实现 |
| ApprovalService.Client（net461 / netstandard2.0 / net8.0） | HTTP 请求、协议模型、错误与取消处理；不引用 UI 框架 | 当前只有服务信息接口；审批 SDK 由 T-016 实现 |
| 审批服务 | 流程版本、执行图、审批规则、审批记录、待办、附件权限及回调投递 | 原型不代表这些生产功能已实现 |

项目引用方向为 **WinUI → 对接类库 → SDK**。SDK 通过 HTTP 访问审批服务，不引用后端程序集；对接类库不引用 WinUI、WebView2 或其他界面框架。WinForms 业务系统复用 net48 对接类库，Web 后端复用 net10.0 对接类库。

## 页面与主流程

| 页面 | 要评审的交互 | 正式实现要点 |
| --- | --- | --- |
| 费用报销 / 采购申请 | 列表选择、新建、修改业务单据、预览流程、提交、撤回、退回后重提、进度 | 业务系统保存单据；审批服务接收数据快照，不能编辑业务字段 |
| 我的待办 | 切换员工后显示对应角标与列表；进入原生审批窗口填写意见 | 服务端鉴权和任务状态检查；重复处理返回冲突后刷新，不靠客户端禁用按钮保证正确性 |
| 内嵌审批 | 桌面内容区打开审批中心；完成后返回单据并查询最新状态 | 业务后端申请短期嵌入令牌；WebView2 仅导航可信审批服务地址；不把 API Key 交给页面脚本 |
| 连接与同步 | 服务连接、本机业务后端开关、环境准备、回调与查询、重复事件 | 离线保留业务草稿；恢复后先查询提交结果，再决定重试，避免盲目重复发起 |
| 对接说明 | 查看每一层做什么，以及提交、审批、回调经过哪些层 | 文件与行数统计应读取实际实现；原型不编造已存在的 API 方法或代码行数 |

业务发起路径：保存业务单据 → 对接类库组织审批输入 → 预览并确认 → SDK 发起 → 保存审批单 ID 与状态 → 展示进度。退回后业务数据在业务客户端修订，经重提接口继续审批；不能把修改单据操作放进审批中心。

审批处理路径：业务身份绑定审批用户 → 查询待办 → 原生窗口调用数据接口，或 WebView2 打开审批中心 → 服务端确认处理结果 → 刷新待办角标与进度。原型的员工切换只用于演示，不是正式鉴权。

## 两种状态同步

- **有业务后端**：审批服务投递事件 → 业务后端验证签名 → 以 eventId 去重 → 更新业务状态和允许回写字段 → 客户端刷新显示。界面退出不影响后端收回调；接口接收方应独立于桌面窗口的生命周期。
- **没有业务后端**：不在桌面上伪装可接收公网回调；打开单据时查询，列表定时刷新。失败保留最后一次确认的状态并显示未同步；恢复网络后重新查询。
- **示例本机后端**：仅用于本机联调，接收回调、取数、取人及钩子；关闭后切换查询模式。它不是生产部署方案，客户端关闭后无法继续接收事件。
- **重复与乱序**：原型只演示重复事件不重复回写。正式事件顺序与并发策略须在契约任务确定；无法确认当前状态时查询服务端，不根据迟到事件把单据倒退。

## 本轮边界

- 原型用浏览器模拟 Fluent 桌面布局，不是可安装的 WinUI 3 程序，没有启动本机 HTTP 服务，也没有真实回调、验签、鉴权或 SDK 调用。
- WebView2 区域以 iframe 展示现有网页原型；它与桌面样例的数据独立，不代表真实令牌交换或双向同步。
- 连接、环境准备、重复回调和查询均为本地模拟；不会安装依赖、读取真实凭据或推送组织及流程。
- 正式 Windows App SDK 下载和 WinUI 项目实施仍按 T-018 与 R8 办理；本轮未下载。免安装打包、系统主题、窗口行为和 WebView2 运行时需在正式 Windows 程序验收。
- 完整 17 个场景、真实打印、附件上传、批量及并发审批由正式任务实现；本页用来评审接入路径与职责，不替代生产测试。
