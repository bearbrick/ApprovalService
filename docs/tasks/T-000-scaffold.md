## 目标

按标签服务的结构搭好审批流服务的架子，让后续任务都是“往已有结构里填实现”，并把协作规则写成文档和自动检查。用户之后让 Codex 接着写。

## 范围

- 仓库结构：frontend、backend、client 三个独立部分，各自的解决方案和编译配置；全仓库共用的 .editorconfig、.gitattributes、.gitignore、global.json、verify.ps1
- 后端六个项目（Contracts、Engine、Domain、Application、Infrastructure、Api）和检查程序；最小链路：健康检查、服务信息、请求 ID 和链路 ID、统一错误格式
- 调用端：SDK（net461、netstandard2.0、net8.0，只有服务信息）、对接类库（net48、net10.0）、检查程序（含端到端）
- 前端：Vue 3 外壳、四个占位页面、顶栏显示连接状态、检查程序
- 文档：README、AGENTS.md、架构、契约、ADR 0001～0006、任务 T-001～T-023
