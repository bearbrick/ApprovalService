## 目标

在内存里能跑通任意执行图：令牌推进、三种网关、回路、子流程、自动节点；所有操作都是命令、处理后产生事件；幂等；超过上限停下。这是引擎“做扎实”的核心（ADR 0004）。

## 范围

可以新建、修改的文件：

- `backend/src/ApprovalService.Engine/Execution/`：审批单状态、令牌、命令、事件、引擎入口
- `backend/src/ApprovalService.Engine/Abstractions/`：节点行为等扩展点接口（docs/architecture.md“扩展点”）
- `backend/tests/ApprovalService.Backend.Checks/EngineScenarioChecks.cs`、`EngineFuzzChecks.cs`（新建），可以写一个读起来像中文剧本的场景小工具

## 验收标准

- [x] 引擎入口是纯的：（当前状态，命令，上下文：时间、ID 生成、组织查询）→（新状态，事件列表）；不碰 IO（R3，ArchitectureChecks 会拦）
- [x] 支持开始、审批（单人）、办理、抄送、排他 / 包容 / 并行网关、回路、子流程（等它结束或不等）、自动节点（产生“待执行动作”事件，结果再通过命令回来）、结束
- [x] 审批单状态：审批中、已通过、已拒绝、已撤回、已终止、待发起人处理、已撤销；任务状态：待处理、已同意、已拒绝、已退回、已转交、已取消
- [x] 幂等：同一请求 ID 的命令重复处理只生效一次
- [x] 一张审批单推进超过 `EngineLimits.MaxStepsPerInstance` 步时停下并标记异常；子流程嵌套超过上限时报错
- [x] 每种节点、网关至少一个场景检查；随机生成流程图和操作顺序跑 1000 次以上，没有卡死（令牌永远等不齐）、没有重复推进、令牌数对得上
- [x] `verify.ps1` 通过（见 AGENTS.md）
- [x] 相关文档已更新（README、架构、契约、设计书受影响的部分）

## 不做

- 退回、加签等操作（T-004）
- 存数据库（T-005）
