# T-004 审批操作全集与委托

状态：待验收
负责人：Codex 2026-10-20
里程碑：M2
依赖：T-003
设计书：§rules

## 目标

设计书第 4 节“审批人能做的”“发起人能做的”“管理员能做的”全部做成命令，加上委托代理、节点允许的操作、意见必填。

## 范围

可以新建、修改的文件：

- `backend/src/ApprovalService.Engine/Commands/`：同意、拒绝、退回（发起人 / 上一步 / 任一走过的节点；重新提交从头走或回到退回的节点；并行分支里的限制）、转交、加签（前 / 后 / 并）、减签、征询和回复、要求补充和补充、抄送、撤销同意、评论和 @、暂存意见、批量同意
- `backend/src/ApprovalService.Engine/Execution/EngineModels.cs`、`EngineRuntime.cs`、`EngineStateCopy.cs`、`EngineWork.cs`：现有唯一命令入口、可持久化状态及事件必须接入新操作；为保持单文件规模，可以按职责将其中类型拆到 `Execution/` 新文件
- 发起人：撤回（可限制“第一个人处理前”）、催办（每小时一次）、重新提交、撤销申请
- 管理员：修改审批人、跳转、终止、离职交接、重发；都要填原因
- 委托代理：时间段、范围、不连环委托、代理人是发起人时的处理
- `backend/tests/ApprovalService.Backend.Checks/OperationChecks*.cs`（新建，按主题拆文件）
- `backend/README.md`、`docs/architecture.md`：记录新命令、状态及应用层接入职责；目前未新增开放接口或流程定义字段，因此 `docs/contracts.md` 与设计书只需核对，无需修改
- `docs/design/approval-service-design.html`：同步用户确认的管理员跳转边界，并行与包容汇合网关不可作为直接跳转目标
