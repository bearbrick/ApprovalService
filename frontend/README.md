# 前端（frontend/）

审批流服务的网页：流程设计器、审批中心（电脑和手机）、管理后台。Vue 3 + TypeScript + Vite，规则见根目录 [AGENTS.md](../AGENTS.md) §5。

## 页面

用地址的 # 部分区分页面（`src/model/routes.ts`）：

| 地址 | 页面 |
| --- | --- |
| `#/` | 审批中心（给审批人用；不能发起审批、不能改业务数据） |
| `#/designer` | 流程设计：统一自由画布，审批数据定义和详情排版 |
| `#/admin` | 管理后台：流程、组织架构、接入应用、日志、统计、系统信息 |
| `#/m`、`#/m/done`、`#/m/cc`、`#/m/me` | 手机端审批中心：卡片布局、筛选与刷新、底部四个标签 |
| `#/m/approvals/{id}` | 手机审批详情：只读业务快照、进度和附件名称，写入动作待接口接入 |

公共框架已具备桌面顶栏/侧栏、手机底部导航、二级页签、空状态、对话框、错误恢复和服务连接状态。顶栏切换工作区，侧栏展示当前工作区的子入口。设计工作台读取并编辑服务端流程草稿；桌面审批中心已接本地工号密码登录和 JWT 四列表、详情及人工任务操作，只有已开通且有参与关系的人员能读取自己的真实记录。未登录显示登录表单；首次登录按服务端要求先改密。令牌只保存在当前页面内存，刷新页面后需重新登录。

中心子页面使用 `#/center/done`、`#/center/cc`、`#/center/started`、`#/center/settings`；手机使用 `#/m/done`、`#/m/cc`、`#/m/me`。详情地址为 `#/center/approvals/{id}` 和 `#/m/approvals/{id}`，只读查询必须由适配器完成授权。

桌面中心的 `CenterPage.vue`、`pages/center/` 和 `model/center.ts` 实现四类列表、服务端标题/编号/业务单号/当前人员可见字段内容搜索、流程/状态/日期筛选、加急排序及只读详情布局。搜索输入短暂防抖后带本人 JWT 请求服务端，非摘要字段也能命中；前端不以摘要再过滤服务端结果。`api/center-adapter.ts` 逐页调用真实中心接口，服务端先做人员和应用授权过滤，再返回已裁剪的摘要与详情、真实人员和来源名称、当前人工环节及任务许可。列表按服务端本人 `isUnread` 加粗，详情显示成功后才显式用 JWT 标记已读；保存失败时仍展示详情并提示刷新重试。详情仅显示服务端明确允许的命令，提交后重新读取详情；列表只允许勾选服务端返回实际任务 ID 的批量同意，逐项展示结果。详情按锁定发布版本中的分组、列数、字段跨度、可见明细列宽和金额大写展示；`center-layout.ts` 再次只按已授权字段解释服务端排版。原单嵌入模式在已授权详情上申请一次性只读 HTTPS 页面，以受限 iframe 展示；钩子或加载失败时显示已授权普通详情。中心不会发起或修改业务单据；附件以当前人员 JWT 经独立权限接口下载或预览，不将令牌写入 URL。

个人设置页读取八类提醒偏好，按本人 JWT 修改邮件和站内开关；每日待办汇总只支持邮件。切换开关时先保留原显示，只有服务端确认后才显示已保存；重新进入页面会从持久接口读取。个人签名、常用意见和委托规则已接入设置页；嵌入会话对个人设置只读，单次签名仍可用于当前办理。

手机中心的 `MobilePage.vue`、`pages/mobile/` 与电脑端使用同一个授权适配器。手机页面支持卡片列表、本地搜索与流程筛选、按钮和顶部下拉刷新、直达详情、离线与失败状态；详情显示业务快照、附件名称和时间线，并可用本人 JWT 提交服务端准许的任务操作。桌面及手机操作表单共用手写画布：可上传单次 PNG，或在本地登录时选用已保存的个人签名；上传后仍需明确点击本次使用，节点必签时前后端均阻止漏签。375 像素外置 Chrome 视觉检查留待 T-012，当前环境的 Chrome 启动受到系统策略阻止。

管理入口见 `src/model/navigation.ts`，例如 `#/admin/org/roles`、`#/admin/outbound/queue`。设计器工作区预留 `#/designer/{flowCode}/{tab}`，支持 design（自由画布）、fields、layout、rules、print、versions。未知页面显示明确的返回入口，手机未知路径仍使用手机外壳。

流程设计器“流程规则”页提供发布前测试模式：管理员以当前草稿、可编辑的假业务 JSON 和每个人工节点的假处理人建立 30 分钟内存会话，在页面逐步完成假任务，或显式给自动动作及子流程提供假结果。页面显示待办、等待和事件；结束模拟会删除内存会话。测试模式不创建真实审批单，也不发送消息或调用业务系统。

管理后台的 `AdminPage.vue`、`pages/admin/` 和 `model/admin.ts` 覆盖管理工作台、流程、组织与绑定、应用接入、运行干预、出站、统计及系统信息/操作日志等入口。管理员使用本地工号密码登录，首次登录先改密；令牌只存在当前页面内存。部门、人员和接入应用列表从有组织管理员权限保护的真实接口读取，页面只搜索安全列；组织页可下载 Excel 模板，上传 CSV/XLSX 文件预检通过后正式导入。应用接入页可登记应用与授权流程、配置允许嵌入来源、带原因启停应用及轮换密钥，明文凭据仅在创建和轮换响应中于页面内存显示一次；操作日志只展示脱敏摘要。工作台复用受保护的报表概览，按浏览器本地今日显示发起与完成总量（保密流程仅计匿名数量）、当前公开待办和今日到期公开逾期量；最近 200 条待发安全摘要中仅列至多 8 条需关注项，明确不将该列表当全量队列统计。其余未接通的管理数据和写入入口明确禁用，失败时显示“—”，不保存假配置。

`#/admin/system/info` 读取服务端真实系统信息；组织管理员可填写原因修改单位名称、上传或移除最多 1 MiB 的 PNG Logo。页面使用内存 JWT 读取图片并生成可释放的预览地址，修订冲突要求刷新。该设置供后续打印页眉使用；中文打印字体上传尚未接入。

统计页使用本地 JWT 同时读取概览、流程、节点和人员四条报表接口；任意请求失败即清除旧结果。浏览器本地时间转成 UTC 半开筛选区间，支持流程、来源应用和发起部门快照过滤。组织管理员可查看全部，部门负责人仅可查看直接负责部门；报表范围会话不能进入其他管理页。保密流程只显示匿名发起量和结束量。页面“导出 Excel”使用当前筛选和报表范围令牌下载同范围四表汇总，文件类型或 ZIP 文件头错误时不保存；下载中禁止重复点击，服务端权限和校验错误显示中文说明。小时持久汇总、趋势与逐单明细导出仍由后续任务完成。

组织人员页的“账号管理”使用已有受保护身份接口，为在职且未开通账号的人员设置临时密码，或作废指定人员现有的访问与刷新令牌。临时密码只在当前表单内存中保留，提交后立即清除；作废会话不会删除账号或修改密码。人员是否已经开通账号由服务端在提交时判定，重复开通会收到冲突提示。

`#/admin/system/security` 先用管理员会话接口核对当前本地组织管理员权限，只提供已落地的“修改我的密码”操作。成功后旧访问和刷新令牌失效，页面使用新密码建立会话；如果重新登录失败，页面退出旧会话。登录方式和令牌策略目前没有管理写接口，页面不展示虚构设置或保存结果。

应用接入页可选择应用并编辑允许嵌入审批中心的网站来源，逐行填写完整 HTTPS origin，本机开发允许 HTTP localhost 或 127.0.0.1；保存时必须填写原因。列表和编辑接口分别读取安全摘要与完整来源，切换应用时重新拉取，服务端按本地组织管理员权限校验并审计变更。

同一页“配置业务原单”独立登记第五个 `documentUrl` 签名钩子和原单 iframe 的完整 HTTPS 来源。原单来源与允许父页面嵌入审批中心的网站名单分开；修改须填写原因，旧应用两项均为空时继续显示普通详情。

组织管理员在接入应用列表打开“接入向导”，可登记应用并一次性保存服务端生成的 API Key 与签名密钥，按已读取旧名单维护该应用的内部人员管理员，选择应用授权的流程生成不含密钥的 C# SDK 示例，并带原因排入签名测试回调。成功后显示 `test-` 事件 ID，可到待发队列查看状态；入队不表示已经送达。已登记的应用管理员可直接打开 `#/admin/apps/test`，使用本地人员账号和已知应用编码发送测试回调；该会话不能读取应用列表、管理员名单或组织级待发队列，服务端每次发送时重新核验在职、应用启用与所属名单。流程发布状态须在真正发起前确认，业务单据仍由业务系统维护。

业务系统绑定页从受保护接口读取人员/部门绑定摘要，可选择应用、当前内部人员或部门并输入外部 ID 建立手工绑定；保存后重新拉取列表。操作日志页展示最近 200 条组织、应用及回调重发变更的时间、操作者、动作、对象和显式原因；原始前后快照不进入浏览器。其他管理模块仍保持明确的未接入状态。

待发队列页读取最近 200 条事件的状态、次数和错误类别，管理员可输入或选择原回调事件 ID、填写原因后手动重排；其他类型待发项不提供手动重发。页面不读取回调正文或目标地址。

正式自由画布流程定义的 TypeScript 副本位于 `src/model/flow.ts`，字段与后端 Contracts 保持一致。流程工作台现已接入自由画布、十类可复制模板（请假、加班、出差、报销、付款、采购、用印、合同、物品领用、质量异常）、节点与路线属性、审批数据及排版、打印设置、服务端草稿和发布预检。模板只包含审批图与数据定义，业务单据仍由业务系统产生；预检通过仅代表前端静态检查通过，正式发布由服务端重新校验并追加不可变版本。

流程管理员在 `#/admin/flows` 使用本地账号登录后可按本人权限查看流程、新建草稿、停启用、预检并导入本服务兼容 BPMN 文件，以及导出草稿或当前发布版。版本历史面板读取不可变发布版本摘要，可填写原因将旧版复制为新草稿；恢复请求同时核对最新草稿修订和当前发布版，并发冲突后可刷新版本历史，当前发布版须经设计器显式发布才会改变。设计器 `#/designer/{flowCode}/{tab}` 从服务端读取草稿，保存时提交预期修订和审计原因，发布时同时核对草稿修订与当前发布版；并发冲突保留页面编辑并显示服务端错误。流程所属部门和分组随草稿保存，部门流程管理员只能管理直接负责部门的流程。

“流程规则”页可为当前流程生成 C# SDK 发起示例，代码从业务系统环境变量读取服务地址和 API Key，不嵌入生成时的明文凭据。示例只处理审批接口调用；接入应用登记、流程授权和正式测试回调仍由管理后台任务接线。

标准 BPMN 建模器只负责绘制和编辑图。选中人工节点后，右侧“找处理人”和“审批规则”由审批服务提供：角色可限定发起部门，连续上级可设置截止职级，找不到处理人时可指定组织人员 ID。流程撤回和退回重提策略在“流程规则”页配置。导出本服务兼容 BPMN 文件时，这些属性随审批扩展保存，导入后继续使用；通用 BPMN 文件不会自动获得这些审批规则。

评审现有画布时可直接打开 `#/designer/EXPENSE/design`、`#/designer/PURCHASE_REQUEST/design` 或 `#/designer/QUALITY_EXCEPTION/design`。默认 `#/` 是审批中心；其真实数据适配器尚未接入，因此不能用首页空状态判断画布完成度。

工作台“流程设置”可选发起人撤回限制（默认审批结束前可撤回，也可限定首位处理人操作前）与退回后重提路线（默认从头，也可回到发起退回的节点）。旧草稿省略这两个字段时使用默认值，前后端发布预检均拒绝未知重提模式；运行时接线由开放接口任务完成。

## 审批数据与详情排版模块

`src/designer/data/ApprovalFieldsEditor.vue` 编辑流程的 `data`：顶层字段、明细表子字段、计算表达式、必传、审批人填写和摘要字段。它提供业务系统提交数据的 JSON 样例；计算字段与审批人填写字段不要求业务系统提交。表达式只作为定义保存，实际解析与计算由后端负责。

`ApprovalDetailLayoutEditor.vue` 编辑 `detailLayout`：自动排版、自定义分组（每行一至三列、字段跨列、明细列宽、金额大写）和嵌入业务系统只读原单的页面编码。自定义模式支持拖放字段，键盘可用分组下拉框和上下移动按钮。右侧实时预览只展示字段结构和类型提示，不使用或伪造真实业务数据。嵌入模式只存页面编码，不接受任意 URL；实际地址及短时身份由业务系统对接提供。

`NodeFieldPermissionsEditor.vue` 编辑人工节点的 `fieldPermissions`，字段路径包括 `tableKey.childKey`。三个组件由流程工作台分别在字段、排版、画布节点属性中挂载，均接收契约镜像类型并通过 `update:data`、`update:detailLayout`、`update:permissions` 返回新对象，不直接修改父级草稿。`data-model.ts` 提供纯函数和场景检查；设计时提示不能代替后端发布校验。审批服务不创建业务单据，也不在设计器提供发起表单。

## 自由画布组件

正式画布组件位于 `src/designer/canvas/BpmnCanvasEditor.vue`，使用固定版本的 `bpmn-js` Modeler 绘制标准 BPMN 常用子集；必须让右下角 bpmn.io 标识保持可见。工作台传入完整 `FlowDefinition`，通过 `inspector` 插槽挂载统一的节点与路线属性面板，并将发布问题高亮到图形；`focusElement(id)` 供问题列表定位。节点与连线由建模器创建、拖动和自动布线，`bpmn-modeler-adapter.ts` 只把图元的 ID、类型、中心坐标与连接关系写回现有审批 JSON，已有审批人规则和字段权限始终保留。首次打开和点击“适应画布”时把完整 BPMN 图居中并留白，不让上方分支贴边裁切。工作台通过 `editCommitted(previousDefinition)`、`undo`、`redo` 统一管理撤销历史。现有 JSON 不含连线折点，重新打开草稿时由建模器按节点坐标重新布线；折点持久化需后续扩展流程契约。BPMN 导出仍使用与后端兼容的标准图形加审批扩展，只接受本服务导出的兼容文件。前端发布预检镜像后端校验，正式发布以服务端为准。

## 后续模块接入方式

1. 在 `model/navigation.ts` 登记入口，在 `model/routes.ts` 明确匹配规则和参数；不要把未知地址悄悄当作首页。
2. 业务页面放进 `pages/` 下对应模块，并在 `App.vue` 的错误边界内选择页面。布局只收页面元数据，不查业务数据，不以导航隐藏替代权限校验。
3. 使用 `requestJson<T>(path, options)` 发送一次 JSON 请求；`getJson` 是 GET 兼容入口。方法、JSON body、headers、timeoutMs、signal 均由调用方传入。不自动重试写操作，不存储凭据。成功响应的结构由各接口入口校验，通用层只保证 JSON 可解析；204 接口应声明 void。
4. `ApiError` 保留 code、message、status、errors、traceId、requestId、kind。取消、超时、网络和无效响应是前端分类；错误码不回写或冒充新服务端契约。页面显示持久错误和明确重试入口。
5. `useServiceConnection` 只请求已有 `/api/v1/info`，默认十五秒超时。重试取消旧请求，旧响应不能覆盖新状态，卸载后取消请求。它表示服务信息可读取，不代表数据库、登录或审批业务就绪。
6. `UiDialog` 由 open 和 close 事件控制，正文与 footer 使用插槽；异步保存的 loading、错误保留和防重复提交由使用方维护。原生 dialog 管理模态焦点，关闭恢复触发元素。
7. `UiErrorBoundary` 用于渲染/生命周期错误恢复，重试会重新挂载子页面；请求异常应由页面显式处理，不以错误边界替代业务错误处理。

普通导航滚动到顶部并聚焦页面标题；前进后退按独立历史条目恢复滚动。桌面窄屏侧栏使用模态导航，隐藏侧栏不占键盘焦点；手机页独立布局且支持底部安全区。

## 检查与边界

审批详情的“审批经过”使用现有 bpmn-js Viewer 绘制服务端已到达的安全子图并高亮当前节点；未来分支和条件不下发。征询回复、减签和退回目标只从当前任务服务端候选列表选择，提交时重验。发起人在“我发起的”详情可催办，服务端限制同一步一小时一次；待办角标从 JWT 列表的 `total` 重取，操作后刷新详情、列表及角标。PDF 预览使用已验权内容的本地 `blob:` 地址，业务原单的网络 iframe 仍只允许登记的 HTTPS 来源。

设置页可用本地 JWT 管理本人常用意见（最多 30 条，每条 500 字）；详情页选择已保存意见后仅填入输入框，由审批人确认现有任务操作。嵌入会话可读取并选择，服务端拒绝嵌入会话修改。

委托设置页输入代理人内部人员 ID、本地起止时间和可选流程编码，转换成 UTC 后交服务端保存。可按标题、编号或业务单号搜索本人待办，勾选已在手或排队的任务逐项转委托并查看每项结果；列表只显示前 20 张匹配审批单，继续缩小搜索可访问其余待办。删除规则不收回已经转出的任务。组织管理员可用受保护的后端接口代指定人员设置或逐项转委托。

`npm run check` 包含路由、HTTP/连接生命周期、对话框/错误边界场景和源码规范；使用已安装的 Vue 编译器与最小渲染宿主，无新增测试依赖。宿主检查不替代浏览器：桌面/手机导航、真实服务连接、ESC 焦点恢复、刷新和前进后退另做浏览器验收，截图位于 `tests/evidence/`。

开发时先在仓库根目录运行 `dotnet run --project backend/src/ApprovalService.Api`，再在本目录运行 `npm run dev`。没有启动后端时连接状态显示失败，可在“服务连接”中重试；其他框架导航仍可使用。

审批中心登录、JWT 查询和人工任务写操作已接入；业务表单由来源系统维护，中心仅显示审批数据快照。列表摘要和详情使用锁定发布版本的字段名称，明细按已授权列展示表格，隐藏列名称不会返回。详情附件只显示服务端确认归属的可见文件，下载及图片/PDF 预览先经现有文件接口用当前 JWT 验权，不把令牌写进文件地址；Office 文件只提供下载。内嵌入口的片段格式为 `/embed/{应用编码}#/center/approvals/{审批单 ID}?embedToken={一次性令牌}`，签发时的 `targetPath` 必须等于 `#/center/approvals/{审批单 ID}`。页面挂载时立即从地址和历史条目清除令牌，兑换后用嵌入 JWT 读取当前应用登记的允许来源；办理成功只向浏览器引用中匹配的登记来源发送 `{instanceId,taskId,status:"changed"}`，不会传递令牌或审批数据。后端 HTML 托管与 CSP 由 T-052 接入，配置完成前开发服务器页面不能作为生产内嵌入口。设置页已接个人签名、常用意见与委托；原单嵌入地址已按 ADR 0022 接通。高保真原型仍在独立的原型任务分支，不会把原型的 localStorage 模拟逻辑搬进产品。
